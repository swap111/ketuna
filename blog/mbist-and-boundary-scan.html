Memory BIST and JTAG boundary scan: testing what scan cannot reach

Physical design & tape-out Intermediate 27 Nov 2026 5 min read By Ketuna

Scan chains test logic but not memory arrays or the solder joints on a board. Learn how on-chip memory BIST runs march algorithms, and how JTAG boundary scan tests board interconnect through four pins.

In this article
  1. Why memories need their own test
  2. March algorithms
  3. JTAG: a standard test port
  4. Boundary scan: testing the board
  5. Try it yourself

Scan chains make flip-flops controllable and observable, and ATPG then covers the logic between them. Two important things stay out of reach. Embedded memories are dense arrays of bit cells, not flip-flops, and their failure modes are different from those of logic gates. And once a chip is soldered onto a board, the connections between chips cannot be probed easily at all. Memory built-in self-test (MBIST) and JTAG boundary scan fill those two gaps, and they often share the same test port.

Why memories need their own test

An SRAM array packs bit cells as tightly as the process allows, so it is where defects are most likely to land. Its faults also behave differently from logic faults:

  • Stuck-at faults: a cell always reads 0 or 1.
  • Transition faults: a cell can be written one way but not the other.
  • Coupling faults: writing or reading one cell disturbs a neighbour.
  • Address decoder faults: an address selects no cell, the wrong cell, or several cells.
  • Data retention faults: a cell loses its value after some time.

You could test a memory from outside through scan, by loading addresses and data into scan flops around it, but a thorough test needs many reads and writes per cell and would take an impractical number of shift cycles. Instead, a small MBIST controller is built next to each memory (or shared across several). It generates addresses and data, runs the test at the memory's own speed, compares read data with expected values, and reports pass or fail through a few bits.

March algorithms

The standard tests are march algorithms: a sequence of elements, each of which walks through all addresses in a fixed order (up or down) and does the same short list of reads and writes at every address. A popular one is March C−, written as:

⇕(w0); ⇑(r0, w1); ⇑(r1, w0); ⇓(r0, w1); ⇓(r1, w0); ⇕(r0)

Here ⇑ means ascending addresses, ⇓ descending, ⇕ either. It performs 10 operations per address, so its run time grows linearly with memory size: 10N operations for N words. The combination of directions and the read-before-write pattern is what lets it detect stuck-at, transition, many coupling faults and address decoder faults.

This Python model runs March C− on a toy 16-word, 1-bit memory with injected faults.

# March C- on a toy memory model, with optional injected faults
N = 16

class Memory:
    def __init__(self, stuck=None, coupling=None):
        self.cells = [0] * N
        self.stuck = stuck          # (addr, value) stuck-at fault
        self.coupling = coupling    # (aggressor, victim): 0->1 sets victim

    def write(self, a, v):
        if self.coupling and a == self.coupling[0] and v == 1 \
                and self.cells[a] == 0:
            vic = self.coupling[1]
            self.cells[vic] = 1
        self.cells[a] = v
        if self.stuck and a == self.stuck[0]:
            self.cells[a] = self.stuck[1]

    def read(self, a):
        return self.cells[a]

def march_c_minus(mem):
    up, down = range(N), range(N - 1, -1, -1)
    # Each element: (address order, [operations])
    elements = [
        (up,   [("w", 0)]),
        (up,   [("r", 0), ("w", 1)]),
        (up,   [("r", 1), ("w", 0)]),
        (down, [("r", 0), ("w", 1)]),
        (down, [("r", 1), ("w", 0)]),
        (up,   [("r", 0)]),
    ]
    for order, ops in elements:
        for a in order:
            for op, v in ops:
                if op == "w":
                    mem.write(a, v)
                elif mem.read(a) != v:
                    return f"FAIL at address {a}, expected {v}"
    return "PASS"

print("good memory:   ", march_c_minus(Memory()))
print("stuck-at-0 @5: ", march_c_minus(Memory(stuck=(5, 0))))
print("coupling 3->9: ", march_c_minus(Memory(coupling=(3, 9))))
print("coupling 9->3: ", march_c_minus(Memory(coupling=(9, 3))))

It prints PASS for the good memory and a failure address for each faulty one. The coupling faults are caught in both directions, aggressor below victim and above it, which is exactly why the algorithm walks the array both up and down. Try deleting the two descending elements: one of the coupling cases will then slip through.

In hardware, the controller is a small state machine with an address counter, a data generator and a comparator. Larger memories often add repair: spare rows or columns that a fuse or register can swap in for a failing one, using the addresses the BIST logged.

JTAG: a standard test port

The IEEE 1149.1 standard, commonly called JTAG, defines a test access port (TAP) with four required signals and one optional:

  • TCK: test clock
  • TMS: test mode select, which steps a small state machine (the TAP controller)
  • TDI: test data in
  • TDO: test data out
  • TRST: optional asynchronous reset of the TAP

Through these pins you load an instruction register, which selects which data register sits between TDI and TDO. Standard instructions include BYPASS (a one-bit register, so a chip can be skipped in a chain of chips), IDCODE (a fixed identification value) and the boundary scan instructions below. Designers add their own instructions too, for example to start MBIST and read its result, or to access a processor's debug logic.

Boundary scan: testing the board

Boundary scan places a scan cell at every digital I/O pin, between the pad and the core logic. These cells form a shift register reachable through the TAP. With the EXTEST instruction, the cells take control of the pins: you shift a pattern into the output cells of one chip, drive it onto the board traces, and capture what arrives at the input cells of the chip on the other end. SAMPLE/PRELOAD lets you observe the pins without disturbing normal operation and preload values before EXTEST.

This finds board-level faults such as opens (a bad solder joint), shorts between adjacent traces, and pins tied the wrong way, all without probes touching the board. Several chips on a board can be chained, TDO of one to TDI of the next, and tested together. The pin-level description of each chip's boundary scan cells is published in a standard description language (BSDL) so that test software knows the chain's structure.

Try it yourself

  1. Run the March C− model above, then add an address decoder fault (two addresses mapped to the same cell) and check that it is detected.
  2. Write a tiny MBIST state machine in Verilog for a 16 × 8 memory model and simulate it in Icarus Verilog or Verilator, with a fault injected by force in the testbench.
  3. Read the JTAG TAP controller's 16-state diagram in an open-source debug project's documentation and trace the TMS sequence that moves from Test-Logic-Reset to Shift-DR.
