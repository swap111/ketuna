Neural networks for hardware engineers: layers as multiply-accumulates

Edge AI Beginner 27 Nov 2026 6 min read By Ketuna

A dense neural network layer is a matrix-vector product. Counting its multiply-accumulates, weights and activations tells you how much compute, flash and RAM the hardware must provide.

In this article
  1. One neuron is a dot product
  2. A dense layer is a matrix-vector product
  3. Counting a small network by hand

Neural networks are usually explained with brains, neurons and pictures of circles joined by lines. That picture is fine for intuition, but it hides what a chip or a microcontroller actually has to do. At inference time a network is a fixed list of arithmetic steps, and almost all of that arithmetic is one operation repeated many times: multiply two numbers and add the result to a running sum. Once you see a layer as a pile of multiply-accumulates, you can size the hardware for it with a pencil.

One neuron is a dot product

A single artificial neuron takes N inputs x1 to xN, multiplies each by its own weight wi, adds them up, adds a bias b, and passes the sum through an activation function f:

y = f(w1x1 + w2x2 + … + wNxN + b)

The sum inside the brackets is a dot product, and each term costs one multiply-accumulate (MAC): multiply wi by xi and add it to an accumulator. A neuron with 40 inputs costs 40 MACs, one bias addition and one activation.

The most common activation in small networks is ReLU, which outputs the input if it is positive and zero otherwise. In hardware that is a sign-bit check and a multiplexer, so it is almost free. The weights and biases were found during training on a PC; the device only uses them.

A dense layer is a matrix-vector product

A dense (fully connected) layer is M neurons that all see the same N inputs. Stack their weight vectors as the rows of an M × N matrix W and the whole layer becomes:

y = f(W·x + b)

where x is the input vector of length N, b is a bias vector of length M and y is the output vector of length M. Each output needs N MACs, so the layer needs M × N MACs and stores M × N weights plus M biases.

Notice something about the data. With one input vector at a time (batch size 1, which is the normal case on a sensor node), every weight is fetched from memory, used in exactly one MAC and never touched again until the next inference. The input vector, by contrast, is reused by every row. That asymmetry decides a lot about hardware design: a dense layer is limited by how fast you can stream weights, not by how fast you can multiply.

Counting a small network by hand

Take a small classifier for a motion sensor: 40 input features, two hidden dense layers of 32 and 16 neurons with ReLU, and 4 output classes. The numbers below follow directly from the layer sizes.

Layer MACs Weights Biases
Dense 40 → 32 1,280 1,280 32
Dense 32 → 16 512 512 16
Dense 16 → 4 64 64 4
Total 1,856 1,856 52

Now turn these into hardware questions.

  • Compute. 1,856 MACs per inference. A core that completes one MAC per cycle at 16 MHz needs about 116 µs, before loop overhead. That tells you immediately that this network is not the bottleneck on any reasonable microcontroller.
  • Weight storage. Weights never change on the device, so they live in flash. Stored as 8-bit integers with 32-bit biases (the usual scheme for small devices), the model takes 1,856 + 52 × 4 = 2,064 bytes.
  • Activation storage. The outputs of each layer are produced at run time, so they need RAM. While layer 1 runs, its 40 inputs and 32 outputs are both alive: 72 bytes at 8 bits each. Layer 2 needs 32 + 16 = 48 bytes. The peak is 72 bytes.

That last point generalises: the RAM you need is set by the largest pair of input and output tensors alive at once, not by the total size of the network. For dense networks this is tiny. For convolutional networks on images or spectrograms, activations become large and RAM, not flash, is often what stops a model from fitting.

A script that does the counting

Counting by hand is the habit to build first. Once you have done it for one network, a few lines of Python will check your work for larger ones:

layers = [(40, 32), (32, 16), (16, 4)]   # (inputs, outputs)

macs = sum(n * m for n, m in layers)
weights = macs                            # dense: one weight per MAC
biases = sum(m for _, m in layers)
flash = weights * 1 + biases * 4          # int8 weights, int32 biases
peak_ram = max(n + m for n, m in layers)  # int8 activations

print(f"MACs={macs} flash={flash} B peak activations={peak_ram} B")
# MACs=1856 flash=2064 B peak activations=72 B

Write the float version of the layer too, np.maximum(0, W @ x + b), because every later step, including an integer implementation in C or an accelerator in Verilog, is checked against it.

What this means for hardware

Three numbers summarise a layer for a hardware engineer: MACs (time and energy in the arithmetic), weight bytes (flash size and memory bandwidth) and activation bytes (RAM). Their ratios matter as much as their sizes.

  • A dense layer does one MAC per weight byte fetched. Adding more multipliers does not help unless the memory can deliver more weights per cycle.
  • A convolution layer reuses each weight at every position of the input, so it does many MACs per weight byte. Parallel MAC hardware pays off there.
  • Precision sets the cost of each MAC. An 8-bit multiplier is far smaller than a 32-bit floating-point unit, which is why small devices run quantized integer models.

Common mistakes when sizing a network:

  • counting parameters and calling that the cost, when convolutions have few parameters but many MACs
  • forgetting activation RAM and discovering on the device that the model fits in flash but not in memory
  • assuming the training accuracy will hold on the device without testing on data from the real sensor

Try it yourself

  1. Pick any small network from a tutorial and fill in the table above for it by hand: MACs, weights, biases and peak activation bytes per layer.
  2. Build the same network in PyTorch with nn.Linear layers, then loop over model.named_parameters() and print each tensor's numel(). Compare with your hand count.
  3. Write the forward pass in numpy as np.maximum(0, W @ x + b) per layer and confirm it matches the PyTorch output for a random input to within floating-point rounding.
  4. Estimate the run time on a microcontroller you know, assuming one MAC per cycle, then ask which of the three numbers would change first if you doubled the input size.
