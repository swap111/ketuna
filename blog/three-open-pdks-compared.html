Three open PDKs and what each is good for

Physical design & tape-out Beginner 27 Nov 2026 5 min read By Ketuna

sky130, gf180 and IHP SG13G2 are open process design kits you can use for real chips. Compare them by process type, voltages, metal stack and typical uses, and learn how to pick one for a project.

A process design kit (PDK) is the bridge between a foundry's manufacturing process and the tools a designer uses. For a long time, every PDK was confidential and licensed under a non-disclosure agreement. Today there are several open PDKs that anyone can download, read and design with, and real chips have been made with them. Choosing between them is one of the first decisions in an open-source chip project, and the right answer depends on what the chip has to do.

What is inside a PDK

Before comparing, it helps to know what you are comparing. A PDK typically contains:

  • Device models for circuit simulation (SPICE models for transistors, resistors, capacitors and any special devices).
  • Design rules as a DRC deck that a layout tool can run.
  • LVS rules that tell a tool how to recognise devices in layout and compare them with a schematic.
  • Extraction rules describing layer thicknesses and dielectrics, for computing wire resistance and capacitance.
  • Technology files such as the tech LEF that place-and-route tools read.
  • Standard-cell libraries with Liberty timing files, LEF footprints, GDS layouts and Verilog models.
  • I/O cells for the pad ring, and often some primitive analog devices and documentation.

All three PDKs below provide these pieces, to different levels of completeness. They are packaged through open tooling (open_pdks, and version managers such as ciel) so a project can pin an exact PDK version.

sky130: the common starting point

sky130 is a 130 nm CMOS process. It has five metal layers plus a local-interconnect layer (li1) under them, 1.8 V core transistors, and higher-voltage devices for I/O and analog use. It has several standard-cell libraries, including sky130_fd_sc_hd (high density, the usual default) and sky130_fd_sc_hs (high speed), plus lower-power and other variants.

What it makes easy:

  • Learning and first tape-outs. It is the most widely used open PDK, so tutorials, example designs, open flows and community help are plentiful. LibreLane's defaults and many example configurations target it.
  • Digital blocks with modest speed requirements, such as small processors, controllers and peripherals.
  • Mixed-signal experiments, since analog devices and models are available alongside the digital libraries.

gf180: higher voltages and simpler stack

gf180 (the open gf180mcu PDK) is a 180 nm CMOS process aimed at microcontroller-style and mixed-signal designs. Its standard-cell libraries are built for higher supply voltages than sky130's core, which suits chips that interface directly with 3.3 V or 5 V systems. It supports different metal stack options; check the PDK documentation for the exact variants and devices.

What it makes easy:

  • Designs that talk to higher-voltage parts without separate level-shifting circuits for every interface.
  • Robust, slower logic and analog where a larger feature size is acceptable or even helpful, for example for some sensor interfaces.
  • A second process to compare against. Hardening the same RTL on sky130 and gf180 is a good way to see how process choice changes area, timing and power.

Because the feature size is larger, the same logic takes more area and runs slower than on a 130 nm process. That trade-off is fine for many control and interface chips.

IHP SG13G2: BiCMOS for RF and analog

IHP SG13G2 is a 130 nm SiGe BiCMOS process. Alongside 1.2 V core CMOS transistors, it offers high-speed silicon-germanium heterojunction bipolar transistors (HBTs), and it has seven metal layers. The PDK is published by a public research institute.

What it makes easy:

  • RF and high-speed analog circuits. HBTs have properties that make them well suited to amplifiers, oscillators and high-frequency front ends, where CMOS alone at this node would struggle.
  • Digital logic at a lower core voltage than sky130, which reduces dynamic power for the same logic, since dynamic power scales with the square of the supply voltage.
  • Designs that need thick upper metals for inductors or low-resistance power routing, which the extra metal layers provide.

The open digital flow supports it, and the PDK includes standard cells and I/O, but the community and the number of examples are smaller than for sky130.

Side by side

sky130 gf180 IHP SG13G2
Process 130 nm CMOS 180 nm CMOS 130 nm SiGe BiCMOS
Core logic voltage 1.8 V Higher (3.3 V or 5 V class) 1.2 V
Notable devices High-voltage devices Higher-voltage devices SiGe HBTs
Good first use Learning, digital, mixed-signal Interfaces, MCU-style chips RF, high-speed analog

Treat this as a qualitative map, not a specification. Check each PDK's documentation for current libraries, device lists and rules.

How to choose

Start from the chip's job, not from the PDK:

  1. What voltages does it interface with? If 5 V I/O matters, gf180 is attractive.
  2. Does it need RF or very fast analog? If yes, look at SG13G2.
  3. Is this a first tape-out or a learning project? sky130's ecosystem will save you the most time.
  4. Which shuttles are available? A PDK is only useful for silicon if there is a way to manufacture with it. Check which open shuttle programmes currently accept each PDK.

Whatever you choose, the flow concepts transfer. Synthesis, floorplanning, placement, clock tree, routing and sign-off work the same way; only the library names, rule decks and numbers change.

Try it yourself

  1. Install sky130 and gf180 with ciel (or open_pdks) and list the standard-cell libraries each provides.
  2. Synthesise the same small design with Yosys against a sky130 library and a gf180 library and compare cell counts and total area with stat -liberty.
  3. Harden it with LibreLane on both PDKs by changing the PDK and STD_CELL_LIBRARY settings, and compare die area and worst slack at the same clock period.
  4. Open a standard cell from each PDK in KLayout and compare the row height and layer stack.
