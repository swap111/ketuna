Implementing activation functions in fixed point: ReLU, sigmoid and lookup tables

Edge AI Advanced 27 Nov 2026 5 min read By Ketuna

ReLU is an exact clamp, any function of an int8 input is an exact 256-entry table, and wider inputs need interpolation. How to build each in fixed point and size its error against the output step.

In this article
  1. ReLU is free and exact
  2. Any function of int8 is a 256-entry table
  3. Wider inputs need interpolation
  4. Choosing by error budget
  5. Pitfalls
  6. Try it yourself

Most of the arithmetic in a neural network is multiply-accumulate, but between layers sit non-linear activation functions, and on an integer-only device each one has to be implemented without floating point. Some are trivial, some are not, and the difference comes down to one question: how many distinct input values can the function see? Answering that, then comparing your approximation error with the quantization step the output already has, tells you how much effort an activation deserves.

ReLU is free and exact

ReLU outputs max(0, x). In a quantized layer, the output is y = zy + round(M × acc), clamped to the int8 range. Real zero corresponds to the integer zy, so ReLU is simply a tighter clamp: [zy, 127] instead of [−128, 127]. ReLU6, which also caps at 6, becomes a clamp to [zy, q(6)], where q(6) is the integer that represents 6.

There is no approximation and no extra operation: the clamp the requantization step needs anyway just uses different limits. This is a big reason small models favour ReLU-family activations. Fusing it into the layer also avoids writing an intermediate tensor to memory and reading it back.

One trap: if the output range was calibrated after ReLU (so it covers only positive values), the output zero point is typically −128, and the fused clamp starts at −128 too. If you fuse but calibrate before ReLU, half the codes are wasted on negative values that the clamp then throws away.

Any function of int8 is a 256-entry table

Sigmoid, tanh, swish or anything else is expensive to compute exactly in fixed point, but if the input is int8, there are only 256 possible inputs. Precompute the output for every one and the function becomes a single table lookup, exact to within the output's own rounding.

Generate the table offline from the quantization parameters. For an input with scale sin and zero point zin, and an output for sigmoid commonly quantized with scale 1/256 and zero point −128 (so 0 to 1 maps onto the full int8 range):

import numpy as np

def sigmoid_lut(s_in, z_in, s_out=1/256, z_out=-128):
    q = np.arange(-128, 128)
    x = s_in * (q - z_in)                       # every possible input
    y = 1 / (1 + np.exp(-x))
    t = np.round(y / s_out) + z_out
    return np.clip(t, -128, 127).astype(np.int8)  # index with q + 128

lut = sigmoid_lut(s_in=0.0625, z_in=0)          # input range [-8, 7.94]

On the device the activation is y = lut[x + 128]: one load, 256 bytes of flash. The error is whatever the output quantization allows: at most half an output step, 1/512 ≈ 0.002, except at the very top, where the largest code represents 255/256 rather than 1.0, so inputs whose sigmoid is above about 0.998 are off by up to 1/256 ≈ 0.004. That is the output format's limit, not the table's.

The same trick covers tanh, swish, GELU or a custom function: the table costs the same 256 bytes whatever is inside it. It also makes bit-exact testing easy, since the reference model can use the very same table.

Wider inputs need interpolation

Some layers feed activations with 16-bit inputs, for example the internal gates of recurrent cells, or a design that keeps more precision before the non-linearity. A full table would need 65,536 entries, too many for flash on a small device. The usual answer is a short table plus linear interpolation, using the function's symmetry to halve the table.

For sigmoid, σ(−x) = 1 − σ(x), so you only need x ≥ 0. Beyond x = 8 the function is within 0.0004 of 1, so a table over [0, 8] covers the useful range. Take the input in Q3.12 format (int16, 12 fractional bits, range [−8, 8)) and a 33-entry table of σ at steps of 0.25, stored in Q15:

#include <stdint.h>

/* SIG_Q15[k] = round(32768 * sigmoid(0.25 * k)), k = 0..32,
   generated offline. */
extern const int16_t SIG_Q15[33];

/* x in Q3.12 (range [-8, 8)); returns sigmoid(x) in Q15 */
int32_t sigmoid_q15(int16_t x)
{
    int32_t ax = x < 0 ? -(int32_t)x : x;
    if (ax > 32767) ax = 32767;              /* only x = -32768 */
    int32_t i = ax >> 10;                    /* 0.25 per entry */
    int32_t f = ax & 1023;                   /* position inside */
    int32_t y = SIG_Q15[i]
              + (((SIG_Q15[i + 1] - SIG_Q15[i]) * f) >> 10);
    return x < 0 ? 32768 - y : y;            /* sigma(-x) = 1 - sigma(x) */
}

In Q3.12, 0.25 is 1,024, so the top bits of |x| select the table entry and the low 10 bits are the fraction for interpolation. Checked against double-precision sigmoid over all 65,536 inputs, the maximum error of this function is about 0.0008. For tanh, use the identity tanh(x) = 2σ(2x) − 1 and share the same table.

Choosing by error budget

How good does the approximation need to be? Compare it with the step of the format the result goes into. If the output is int8 with scale 1/256, one step is about 0.0039, and rounding already introduces up to half that. An approximation whose error is well below half a step barely changes any output code.

For sigmoid over [−8, 8], computed in numpy:

Approximation Max error Cost
"Hard sigmoid" clip(x/4 + 0.5, 0, 1) about 0.119 one shift, one add, a clamp
clip(0.2x + 0.5, 0, 1) about 0.076 one multiply, one add, a clamp
9-point table on [0, 8] + interpolation about 0.012 small table, one multiply
17-point table + interpolation about 0.003 small table, one multiply
33-point table + interpolation about 0.0007 small table, one multiply

The hard sigmoid's error is many output steps, so a model trained with true sigmoid and deployed with hard sigmoid will behave differently. It is perfectly usable when the model is trained with it, which is what some small architectures do. The 33-point table sits comfortably below half an int8 step and costs 66 bytes.

Pitfalls

  • deploying a cheap approximation for a model trained with the exact function, without re-measuring accuracy
  • building a table from one set of quantization parameters and reusing it after the model was re-quantized
  • forgetting the saturated tails: a table that stops at x = 4 leaves an error of about 0.018 at the edge
  • interpolating with a product that overflows: check the width of (t[i+1] − t[i]) × f
  • testing an approximation only at table points, where its error is zero by construction

Try it yourself

  1. Run sigmoid_lut for an input scale of your choice and plot the dequantized output against the exact sigmoid.
  2. Generate the 33-entry Q15 table with numpy, compile sigmoid_q15 with GCC, loop over all int16 inputs, and measure the maximum error yourself.
  3. Replace the interpolation with a nearest-entry lookup and measure how much the error grows.
  4. Swap the sigmoid in a small trained model for the hard sigmoid in PyTorch and compare test accuracy before and after fine-tuning.
