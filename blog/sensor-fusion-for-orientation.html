Sensor fusion basics: complementary and Kalman filters for orientation

Edge AI Intermediate 27 Nov 2026 5 min read By Ketuna

A gyroscope drifts and an accelerometer is noisy, but together they give a stable tilt estimate. How a complementary filter and a two-state Kalman filter combine them, with C and Python you can test.

A drone's flight controller needs to know, hundreds of times a second, how far it is tilted. Small inertial measurement units (IMUs) give it two sensors that each answer that question badly in a different way. The gyroscope measures rotation rate precisely but has to be integrated, so its errors pile up. The accelerometer can tell which way gravity points, so it never drifts, but it is noisy and fooled by every vibration and manoeuvre. Sensor fusion combines them so that each covers the other's weakness, and the two classic ways to do that are short enough to write in an afternoon.

Why neither sensor works alone

Gyroscope. A gyro reports angular rate ω in degrees per second. Integrating it, angle += ω × dt, gives orientation, and over a fraction of a second this is very accurate. But every gyro has a small bias, a non-zero reading when it is still, and integration turns a constant bias into a growing error. With an illustrative bias of 0.5 °/s, the angle is off by 30° after one minute.

Accelerometer. At rest, an accelerometer measures only gravity, so the tilt follows from trigonometry. For one common axis convention:

roll = atan2(ay, az), pitch = atan2(−ax, √(ay2 + az2))

Check the axis directions on your own sensor; conventions differ. This estimate does not drift, but it is noisy, and whenever the device accelerates, or the motors shake the frame, the measured vector is no longer just gravity and the angle jumps.

So the gyro is trustworthy at high frequencies (short time scales) and the accelerometer at low frequencies (long time scales). That observation is the whole idea of the first filter.

The complementary filter

The complementary filter high-pass filters the gyro-integrated angle and low-pass filters the accelerometer angle, with the same time constant so that the two filters add up to exactly one at every frequency. In code it collapses to one line per axis:

angle = α × (angle + ω × dt) + (1 − α) × angleacc

The coefficient comes from the crossover time constant τ and the sample period dt: α = τ / (τ + dt). For a 500 Hz loop (dt = 2 ms) and τ = 0.5 s, α = 0.5 / 0.502 ≈ 0.996. Each step trusts the gyro 99.6 % and nudges the estimate 0.4 % towards the accelerometer, which is enough to pull out drift over a second or so while averaging away accelerometer noise.

The bias does not vanish entirely. In steady state the filter settles where the gyro's push each step balances the accelerometer's pull, which leaves an error of bias × τ: with 0.5 °/s and τ = 0.5 s, about 0.25°, compared with 30° after a minute for the gyro alone. A shorter τ reduces that error but lets more accelerometer noise and vibration through.

typedef struct { float angle, alpha; } cf_t;

void cf_init(cf_t *f, float tau, float dt)
{
    f->angle = 0.0f;
    f->alpha = tau / (tau + dt);
}

/* gyro_dps: rate in deg/s; acc_deg: tilt from atan2 in degrees */
float cf_update(cf_t *f, float gyro_dps, float acc_deg, float dt)
{
    f->angle = f->alpha * (f->angle + gyro_dps * dt)
             + (1.0f - f->alpha) * acc_deg;
    return f->angle;
}

The Kalman filter view

A Kalman filter does the same blending, but chooses the weight each step from explicit noise models instead of a fixed α, and it can estimate quantities you cannot measure directly, such as the gyro bias. For tilt on one axis, a common formulation has a two-element state: the angle and the gyro bias.

  • Predict: advance the angle with the gyro reading minus the current bias estimate, and grow the uncertainty P by the process noise Q, which says how much you distrust the gyro model.
  • Update: compare the prediction with the accelerometer angle. The Kalman gain K weighs the correction by how uncertain the prediction is relative to the measurement noise R. Both the angle and the bias are corrected.
import numpy as np

def kalman_angle(gyro, acc_angle, dt, q_angle=1e-4, q_bias=1e-6, r=0.03):
    x = np.zeros(2)                    # [angle (deg), bias (deg/s)]
    P = np.eye(2)
    F = np.array([[1, -dt], [0, 1]])
    B = np.array([dt, 0])
    H = np.array([1.0, 0.0])
    Q = np.diag([q_angle, q_bias])
    out = []
    for w, z in zip(gyro, acc_angle):
        x = F @ x + B * w              # predict with the gyro
        P = F @ P @ F.T + Q
        K = P @ H / (H @ P @ H + r)    # Kalman gain
        x = x + K * (z - H @ x)        # correct with the accelerometer
        P = P - np.outer(K, H) @ P
        out.append(x.copy())
    return np.array(out)

On synthetic data with a 0.5 °/s bias, this filter's bias estimate converges close to 0.5, and subtracting it removes the steady offset the complementary filter keeps. Do not assume it is automatically better: with poorly chosen Q and R it can do worse than a well-tuned complementary filter. Its strengths are a principled way to tune, a bias estimate you can log, and a clean path to more states (three axes, magnetometer, quaternion orientation) when you need them.

Practical notes and limits

  • Run at a fixed rate. Both filters assume a known dt. Drive them from a timer interrupt, and measure dt if jitter is possible.
  • Gate the accelerometer. If the measured acceleration magnitude is far from 1 g, the device is manoeuvring; reduce or skip the accelerometer correction for that step.
  • Calibrate first. Average the gyro at rest at start-up to remove most of the bias before the filter ever runs.
  • Yaw is different. Gravity says nothing about heading, so yaw needs a magnetometer or another reference.

A safety note: a flight controller's attitude estimate keeps an aircraft in the air. Test fusion code on a bench rig and in simulation, with propellers removed, long before it flies, and follow the rules that apply to flying drones where you are.

Try it yourself

  1. Generate synthetic data in numpy (a slow sinusoidal tilt, a gyro with bias and noise, a noisy accelerometer angle) and compare gyro-only integration, the complementary filter and the Kalman filter.
  2. Vary τ and plot the trade-off between steady offset and noise.
  3. Log real data from an IMU breakout board at a fixed rate and run both filters offline before porting either to firmware.
  4. Port cf_update to a microcontroller and check its output against the Python version on the same logged data.
