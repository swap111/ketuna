Int8 quantization explained: scale, zero point and what you lose

Edge AI Intermediate 27 Nov 2026 5 min read By Ketuna

How real-valued weights and activations are mapped to 8-bit integers with a scale and a zero point, how symmetric and asymmetric schemes differ, and where the accuracy actually goes.

In this article

  2. A worked example
  3. Symmetric and asymmetric schemes
  4. Where the accuracy goes
  5. Try it yourself

A trained network arrives as 32-bit floating-point numbers. A small microcontroller may have no floating-point unit, a few hundred kilobytes of memory and a tight energy budget, and an accelerator built for it will almost certainly use 8-bit integer multipliers. Quantization is the bridge: it replaces each real number with an 8-bit integer plus a little bookkeeping. The bookkeeping is just two numbers, a scale and a zero point, and understanding them is what lets you debug a model that runs on the device but gives the wrong answers.

The affine mapping

Int8 quantization uses one linear rule to go between a real value r and an integer q:

r = s × (q − z)

Here s is the scale, a positive real number that says how much one integer step is worth, and z is the zero point, the integer that represents real 0. Going the other way, you quantize with rounding and clamping:

q = clamp(round(r / s) + z, −128, 127)

To pick s and z you need the range of values the tensor takes, [rmin, rmax]. Spread that range over the 256 available codes:

  • s = (rmax − rmin) / 255
  • z = round(−rmin / s) − 128

Because z is an integer, real 0 maps to an integer exactly. That matters: zero padding in convolutions and the zeros that ReLU produces must stay exactly zero, or every padded border pixel would add a small error.

A worked example

Suppose calibration showed an activation tensor lies in [−1, 3]. Then s = 4 / 255 ≈ 0.015686 and z = round(63.75) − 128 = −64. Quantize a few values and convert them back:

Real r q s × (q − z) Error
0.0 −64 0.0 0
0.5 −32 0.50196 +0.00196
1.234 15 1.23922 +0.00522
3.0 127 2.99608 −0.00392

Every error is at most half a step, s / 2 ≈ 0.0078, because rounding can be off by at most half a code. This is the rounding error, and it is the price you always pay. You can check the table with a few lines of Python:

import numpy as np

def qparams(rmin, rmax):
    s = (rmax - rmin) / 255
    z = int(round(-rmin / s)) - 128
    return s, z

def quantize(r, s, z):
    return np.clip(np.round(r / s) + z, -128, 127).astype(np.int8)

def dequantize(q, s, z):
    return s * (q.astype(np.int32) - z)

s, z = qparams(-1.0, 3.0)
r = np.array([0.0, 0.5, 1.234, 3.0])
q = quantize(r, s, z)
print(q, dequantize(q, s, z) - r)

Symmetric and asymmetric schemes

The scheme above is asymmetric: the range does not have to be centred on zero, so z can be anything. The alternative is symmetric quantization, which forces z = 0 and uses s = max|r| / 127.

Why would you give up flexibility? Look at what a multiply-accumulate becomes. With real inputs x and weights w, the integer dot product is Σ (qx − zx)(qw − zw). If zw is not zero, expanding the product gives cross terms that cost extra work per output. If weights are symmetric, zw = 0 and the term collapses to Σ (qx − zx) qw, and the zx part can be folded into the bias ahead of time. Weights are also usually spread roughly evenly around zero, so symmetric costs them little.

Activations are different. After a ReLU they are never negative. Take a range of [0, 6]:

  • asymmetric: s = 6 / 255 ≈ 0.0235, all 256 codes used
  • symmetric: s = 6 / 127 ≈ 0.0472, and the 128 negative codes are never used

The symmetric version has twice the step size and therefore twice the rounding error for the same tensor. That is why the common int8 scheme uses symmetric weights and asymmetric activations.

A related choice is per-tensor versus per-channel scales for weights. If one output channel of a convolution has weights in ±0.05 and another in ±2, a single scale wastes almost all the codes on the small channel. Giving each output channel its own scale costs one extra multiplier constant per channel and usually recovers most of the loss.

Where the accuracy goes

Quantization error has two sources, and they pull in opposite directions.

  1. Rounding error grows with the step size s, which grows with the range you choose.
  2. Clipping error appears when real values fall outside the range and get clamped to −128 or 127.

If a tensor is mostly in ±1 but a rare outlier reaches 20, setting the range to ±20 makes the step twenty times larger for every ordinary value. Clipping the outlier instead may cost less overall. Choosing the range is therefore a trade-off, and it is the main thing calibration tools decide.

The errors then accumulate through the network. Each layer adds its own rounding, and the following layer amplifies or damps it depending on its weights. In practice, int8 with per-channel weights is often close to the float model for convolutional networks, but "often" is not a promise for your model: you measure it on your test set.

Common mistakes:

  • forgetting to subtract the input zero point, which biases every output by zx × Σ qw
  • feeding the device raw sensor features without quantizing them with the input tensor's own scale and zero point
  • computing ranges from a few clean samples, so real inputs get clipped in the field
  • rounding differently in the Python reference and the device code, which breaks bit-exact comparison

Try it yourself

  1. Run the script above, then change the range to [−1, 30] and watch the error on 0.5 and 1.234 grow.
  2. Generate 10,000 samples from np.random.laplace(0, 0.5, 10000), quantize them with the full min-max range and with a range clipped at the 99.9th percentile of |r|, and compare the mean squared error of the two.
  3. Quantize a ReLU output range of [0, 6] both symmetrically and asymmetrically and confirm that the symmetric step is about twice as large.
  4. Take a small trained PyTorch model, quantize one layer's weights per tensor and per channel, and compare the worst-case error across channels.
