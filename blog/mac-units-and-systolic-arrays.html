MAC units and systolic arrays: how ML accelerators reuse data

Edge AI Intermediate 27 Nov 2026 5 min read By Ketuna

A systolic array is a grid of multiply-accumulate cells that pass operands to their neighbours, so each value fetched from memory feeds a whole row or column. The PE in Verilog, the skew, and a cycle count.

In this article

Putting sixteen multipliers on a chip is easy. Keeping all sixteen busy is the hard part, because each multiply needs two operands, and memories cannot deliver thirty-two fresh bytes every cycle without becoming large, slow and power-hungry. A systolic array solves this by making operands travel: a value is read from memory once and then handed from cell to cell, doing useful work at every stop. This article builds the idea from a single multiply-accumulate unit up to a small array you can model in a few lines of Python.

The MAC unit

The basic building block of every ML accelerator is the multiply-accumulate (MAC) unit: a multiplier feeding an adder whose output goes back into an accumulator register. Each cycle it computes acc ← acc + a × b. For int8 inference, a and b are signed 8-bit numbers and the accumulator is wider, typically 24 to 32 bits, because sums of many 16-bit products grow quickly.

Why int8 matters here: the area and energy of an array multiplier grow roughly with the square of the operand width, so an 8 × 8 multiplier is a small fraction of a 32-bit one. That is what lets an accelerator afford many of them.

A matrix multiply C = A · B, where A is M × K and B is K × N, needs M × N × K MACs. Every layer you care about, dense or convolutional, can be arranged as such a product. The question is how to feed the MACs.

Why parallel MACs starve

Imagine 16 independent MAC units, each computing one element of a 4 × 4 output tile. Every cycle, unit (i, j) needs a[i][k] and b[k][j]. Look at what is shared: all four units in row i need the same a[i][k], and all four in column j need the same b[k][j]. If each unit fetches its own operands, the memory must deliver 32 bytes per cycle, though only 8 of them are distinct.

You could broadcast each value over long wires to every unit that needs it. That works for small arrays, but long, heavily loaded wires are slow and burn energy, and the problem gets worse as the array grows. The systolic answer is to replace broadcast with a relay.

The systolic idea

In a systolic array, the processing elements (PEs) are arranged in a grid and each one connects only to its immediate neighbours. In the output-stationary form used here, each PE owns one output element and keeps its accumulator in place:

  • elements of A enter at the left edge and move one PE to the right each cycle
  • elements of B enter at the top edge and move one PE down each cycle
  • each PE multiplies the pair passing through it and adds the product to its accumulator

The skew is what makes it work. Row i of A is delayed by i cycles and column j of B by j cycles, so a[i][k] and b[k][j] both reach PE (i, j) at cycle t = i + j + k. Work sweeps across the array as a diagonal wavefront. Each value read from memory is used N times as it crosses the array, so the memory only supplies 2N values per cycle for N2 MACs.

One PE in Verilog

Each PE is two pipeline registers and a MAC:

module pe #(parameter AW = 24) (
  input  wire                 clk,
  input  wire                 clear,   // start a new output
  input  wire signed [7:0]    a_in,    // from the left neighbour
  input  wire signed [7:0]    b_in,    // from the neighbour above
  output reg  signed [7:0]    a_out,   // to the right neighbour
  output reg  signed [7:0]    b_out,   // to the neighbour below
  output reg  signed [AW-1:0] acc      // this PE's output element
);
  always @(posedge clk) begin
    a_out <= a_in;
    b_out <= b_in;
    acc   <= (clear ? 0 : acc) + a_in * b_in;
  end
endmodule

Wiring an N × N grid is two nested generate loops connecting a_out of PE (i, j) to a_in of PE (i, j+1), and b_out to b_in of PE (i+1, j). Every wire is short and goes to exactly one place, which is why systolic arrays reach high clock rates with modest effort in physical design.

Counting cycles and utilisation

The last PE, (N−1, N−1), receives its final pair at cycle (N−1) + (N−1) + (K−1), so a tile needs K + 2(N − 1) cycles before the results are ready to drain. Model it before writing RTL:

import numpy as np

def systolic_os(A, B):
    N, K = A.shape
    a = np.zeros((N, N), dtype=np.int64)
    b = np.zeros((N, N), dtype=np.int64)
    acc = np.zeros((N, N), dtype=np.int64)
    cycles = K + 2 * (N - 1)
    for t in range(cycles):
        a = np.roll(a, 1, axis=1)          # a moves one PE right
        b = np.roll(b, 1, axis=0)          # b moves one PE down
        for i in range(N):                 # skewed feed, left edge
            k = t - i
            a[i, 0] = A[i, k] if 0 <= k < K else 0
        for j in range(N):                 # skewed feed, top edge
            k = t - j
            b[0, j] = B[k, j] if 0 <= k < K else 0
        acc += a * b                       # every PE does one MAC
    return acc, cycles

rng = np.random.default_rng(0)
A = rng.integers(-128, 128, (4, 64))
B = rng.integers(-128, 128, (64, 4))
C, cycles = systolic_os(A, B)
print(np.array_equal(C, A @ B), cycles)    # True 70

For N = 4 and K = 64, the array does 4 × 4 × 64 = 1,024 MACs in 70 cycles. Its peak is 16 MACs per cycle, so utilisation is 1,024 / (16 × 70) ≈ 91 %. With K = 8 the same array needs 14 cycles for 128 MACs, about 57 %. The fill and drain of the wavefront are a fixed cost, so short reductions and small layers waste a large array.

Pitfalls to watch for:

  • forgetting the skew, so operands meet the wrong partners and results are quietly wrong
  • sizing the accumulator for typical data instead of the worst-case sum of products
  • quoting peak MACs per cycle without the utilisation for real layer shapes
  • using a 2-D array for batch-1 dense layers, where there is no second dimension to reuse weights across and most PEs sit idle

Try it yourself

  1. Run the Python model above and change N and K to see how utilisation moves.
  2. Simulate the pe module with Icarus Verilog (iverilog -g2005, then vvp) and check that −128 × −128 accumulates correctly with a 24-bit acc.
  3. Build a 2 × 2 array with generate loops, drive it with skewed inputs from a testbench, and compare the result with numpy.
  4. Synthesise the 2 × 2 array with Yosys (synth -top your module, then stat) and see how the cell count splits between multipliers and registers.
