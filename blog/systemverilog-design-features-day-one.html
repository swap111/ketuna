Five SystemVerilog design features worth using from day one

Digital & VLSI design Beginner 27 Nov 2026 5 min read By Ketuna

logic, always_ff and always_comb, enums, structs with packages, and unique case each turn a class of silent RTL bug into a tool error or warning. Here is what each one catches.

Many students learn plain Verilog in college and then meet SystemVerilog only as "the verification language". That is a missed opportunity. SystemVerilog also added a small set of design features that are synthesizable in open-source and commercial tools alike, and each one exists to catch a specific kind of mistake. You do not need classes or randomisation to benefit. These five are worth using in your very first module.

1. logic instead of reg and wire

In Verilog you must decide whether a signal is a wire (driven by assign or a port) or a reg (assigned in an always block). The name reg misleads beginners into thinking it means a register, which it does not: a reg assigned in a combinational block is just a wire.

SystemVerilog's logic type works in both places:

logic [7:0] count;      // assigned in always_ff
logic       carry;      // assigned with assign

What it catches: a logic variable may have only one driver when it is assigned procedurally or by a continuous assignment, so tools report an error if two assign statements, or an assign and an always block, drive the same logic signal. In Verilog, two assigns on one wire are legal and give you contention, an X in simulation and a short circuit in hardware. Use wire only when you genuinely want multiple drivers, such as a tri-state bus.

2. always_ff and always_comb

Verilog's always block does not say what it is meant to be. SystemVerilog adds specific versions:

always_ff @(posedge clk or negedge rst_n)
  if (!rst_n) count <= '0;
  else        count <= count + 1'b1;

always_comb begin
  next = state;              // default first
  if (go) next = RUN;
end

What they catch:

  • always_comb builds its own sensitivity list, so you cannot forget a signal and get a simulation that disagrees with the hardware.
  • Tools warn if an always_comb block implies a latch, for example from a missing else.
  • always_ff must have exactly one event control, and tools can warn when its contents do not look like a flip-flop.
  • A variable assigned in an always_comb or always_ff block may not be assigned anywhere else.

There is also always_latch for the rare case when a latch is intended, which makes that intent visible in code review.

3. Enumerated types for states

A state machine written with localparam codes and a 2-bit reg lets you assign any 2-bit value to the state, including a typo. An enum gives the states names and a type:

typedef enum logic [1:0] {IDLE, LOAD, RUN, DONE} state_t;
state_t state, next;

What it catches:

  • Assigning a plain number, or a value of a different enum type, to state is illegal without an explicit cast, and tools report it as an error or at least a warning, depending on the tool.
  • Waveform viewers and $display with %s and state.name() show RUN instead of 2'b10, which makes debugging much faster.
  • Synthesis and lint tools recognise the variable as a state register, which helps FSM extraction and coverage.

4. Structs and packages

A pipeline often carries several related fields together: data, a valid bit, a channel number, a last flag. Writing them as separate signals means every stage repeats four declarations and four assignments, and forgetting one is easy. A packed struct groups them:

package sensor_pkg;
  typedef struct packed {
    logic [15:0] sample;
    logic [2:0]  channel;
    logic        last;
  } beat_t;
endpackage

module stage
  import sensor_pkg::*;
(
  input  logic  clk,
  input  beat_t in_beat,
  output beat_t out_beat
);
  always_ff @(posedge clk) out_beat <= in_beat;  // all fields at once
endmodule

A package holds types, parameters and functions that several modules share, so every module agrees on the layout of beat_t.

What they catch: a field added to the struct reaches every stage automatically; there is no stage where you forgot to pipeline the new signal. Port connections between modules using beat_t cannot be wired to the wrong field. A packed struct is still just a bit vector underneath, so it synthesises to exactly the same flops as separate signals.

5. unique case and priority case

A plain case statement says nothing about whether its items overlap, or whether one of them always matches. SystemVerilog adds two qualifiers:

always_comb begin
  y = '0;
  unique case (sel)
    2'b00: y = a;
    2'b01: y = b;
    2'b10: y = c;
    2'b11: y = d;
  endcase
end
  • unique case tells the tools that exactly one item matches for every value that can occur. Simulators report a violation at run time if no item matches, or if more than one does. Synthesis can then build a parallel mux instead of a priority chain.
  • priority case says the items are checked in order and at least one will match.

What they catch: a selector value you did not think of, such as X from an uninitialised register, or a later edit that makes two items overlap. Be careful, though: unique also gives synthesis permission to optimise as if the unexpected values never happen, so the simulation warning is not something to ignore. Read every violation message, and fix the cause rather than removing the keyword.

Tool support and common mistakes

All five features are supported by the open-source tools used in this program, such as Verilator and Yosys, though support for some newer SystemVerilog constructs varies by tool and version. If a construct is rejected, check the tool's documentation before rewriting your design around it. A short "hello world" file that uses each feature, run through every tool in your flow, saves surprises later.

Mistakes to avoid when you start:

  • Using logic for a bus that really does have several tri-state drivers
  • Adding unique to silence a lint warning without checking that the case really is complete
  • Declaring the same struct separately in two modules instead of in one package, so they drift apart
  • Forgetting that an enum's underlying width must hold all its values

Try it yourself

  1. Write a small FSM with an enum, always_ff, always_comb and unique case, and lint it with verilator --lint-only -Wall.
  2. Deliberately add a second assign to a logic signal, and a missing else in the always_comb block. Note the exact message each tool gives.
  3. Synthesise the FSM with Yosys using read_verilog -sv and confirm that the struct-based stage module maps to the same number of flops as the total struct width.
