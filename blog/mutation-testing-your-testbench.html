Is your testbench any good? Checking it by injecting bugs on purpose

Verification Intermediate 27 Nov 2026 5 min read By Ketuna

Mutation testing seeds small deliberate faults into the RTL and checks that some test fails for each one. Learn the common mutation operators, how to read survivors, and a small Python script to run it.

  3. A worked example

  6. Try it yourself

A passing regression tells you that no test noticed a problem. It does not tell you whether any test would have noticed. Coverage helps, but a line can be executed with its result never checked, and a scoreboard can be quietly disconnected while every coverage bin fills up. Mutation testing measures the thing you actually care about: if the design had a bug here, would the testbench catch it? It answers by putting bugs in on purpose and seeing what happens.

The idea

Take the RTL and make one small change that a real designer might plausibly make by mistake: flip a comparison, change a constant, invert a condition. That modified design is a mutant. Run the regression against it.

  • If at least one test fails, the mutant is killed. Good: the testbench can detect that kind of bug at that place.
  • If every test passes, the mutant survived. Either the testbench has a gap, or the change does not actually alter behaviour.

Repeat for many mutants across the design. The surviving mutants are a precise list of places where a bug could hide from your tests.

Typical mutation operators

Mutation operators are the rules for making changes. For RTL, useful ones include:

Operator Example Bug it imitates
Relational swap >= becomes > Off-by-one at a boundary
Arithmetic swap + becomes - Wrong operation
Constant change 4'd9 becomes 4'd8 Wrong limit or reset value
Condition inversion if (en) becomes if (!en) Wrong polarity
Logical swap && becomes \|\| Wrong combination of conditions
Assignment removal delete one non-blocking assignment Missing update
Stuck-at replace a signal with 0 or 1 Broken connection

Each mutant should differ from the original in exactly one place, so a survivor points at one location.

A worked example

Take a FIFO with its testbench, and generate twenty mutants, one per operator application. The numbers here are made up for illustration.

Suppose 17 are killed and 3 survive. You inspect the survivors:

  1. count == DEPTH changed to count >= DEPTH in the full flag. The count can never exceed DEPTH in this design, so both expressions always give the same answer. This is an equivalent mutant: it does not change behaviour, and no test could kill it.
  2. The almost_full threshold changed from 6 to 5. The output is driven, but no test or assertion ever compares it with anything; the scoreboard checks only data. A real gap.
  3. wr_en && !full changed to wr_en. Writes when full are no longer blocked. No test ever writes while full. A real gap.

The mutation score excludes equivalent mutants: 17 killed out of 19 non-equivalent ones, about 89%. The score matters less than the two survivors, each of which points at a missing check: one that compares almost_full with the occupancy, and a test that writes while full and checks the write is ignored.

A small mutation runner

You can run mutation testing with nothing more than Python and your existing regression command. This script applies simple text substitutions one at a time, runs the tests, and reports survivors.

import re, shutil, subprocess

RTL = "rtl/fifo.v"
OPERATORS = [(r">=", ">"), (r"<=(?!\s*[^=]*;)", "<"),   # crude guard
             (r"&&", "||"), (r"\+ 1'b1", "+ 1'b0"),
             (r"!full", "1'b1"), (r"!empty", "1'b1")]

def mutants(text):
    for pat, rep in OPERATORS:
        for m in re.finditer(pat, text):
            yield (m.start(), pat, rep,
                   text[:m.start()] + rep + text[m.end():])

def run_tests():
    r = subprocess.run(["make", "-s", "test"], capture_output=True)
    return r.returncode == 0

original = open(RTL).read()
shutil.copy(RTL, RTL + ".orig")
survivors = []
try:
    for pos, pat, rep, mutated in mutants(original):
        open(RTL, "w").write(mutated)
        if run_tests():
            line = original.count("\n", 0, pos) + 1
            survivors.append(f"line {line}: {pat} -> {rep}")
finally:
    shutil.copy(RTL + ".orig", RTL)        # always restore

print(f"{len(survivors)} survivors")
print("\n".join(survivors))

Text substitution is crude: the <= pattern, for instance, risks hitting non-blocking assignments, and the guard shown is only a rough attempt to skip them. It is enough to learn the method on a small block. For anything larger, work at the netlist level instead. Yosys has a mutate command that lists and applies mutations to a design's internal representation, and the open-source mcy (Mutation Cover with Yosys) framework builds a full mutation flow around it, including a step that uses formal checks to filter out equivalent mutants.

Make sure make test returns a non-zero exit status when any test fails; otherwise every mutant appears to survive. Check this once by hand before trusting the script.

Using the results well

  • Start with the original passing. Mutation testing assumes a green regression. A failing baseline makes every result meaningless.
  • Expect equivalent mutants. Some survivors cannot be killed. Mark them, with a one-line reason, so nobody investigates them twice.
  • Fix gaps with checks, not just stimulus. Many survivors are executed but not checked. The fix is often a new assertion or a scoreboard comparison, rather than more random traffic.
  • Control the cost. Each mutant is a full regression run. Use your fast smoke tests, run mutants in parallel, and focus on the control logic where bugs matter most.
  • Rerun after big testbench changes. A testbench refactor can silently disconnect a check. Mutation testing notices.

Try it yourself

  1. Take a small FIFO or counter with a cocotb testbench that passes on Icarus Verilog, and make sure make test exits non-zero on failure.
  2. Run the script above, list the survivors, and classify each as a gap or an equivalent mutant.
  3. Add one test or assertion per real gap and rerun until only equivalent mutants survive.
  4. Try Yosys's mutate -list on the same design to see the mutations it proposes, and compare them with your text-based ones.
