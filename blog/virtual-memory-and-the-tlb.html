Virtual memory and the TLB: translating addresses without slowing down

Computer architecture & RISC-V Advanced 27 Nov 2026 6 min read By Ketuna

A RISC-V Sv32 page walk worked step by step, why every access cannot afford it, and the TLB choices that hide it (reach, superpages, ASIDs, fences, the VIPT limit).

In this article

  2. A page walk worked by hand
  3. The TLB and what limits it
  4. Design choices that keep the TLB correct and fast
  5. Common mistakes
  6. Try it yourself

Virtual memory gives each process its own address space, with protection between them and the freedom for the operating system to place pages wherever it likes in physical memory. The price is that every load, store and instruction fetch must be translated from a virtual to a physical address. If translation meant reading page tables from memory every time, a single load would turn into three memory accesses. The translation lookaside buffer (TLB) is what makes the scheme affordable, and its design is a set of trade-offs worth understanding. This article uses the RISC-V Sv32 scheme for 32-bit systems as the concrete example.

Sv32 in one picture

Sv32 uses 4 KiB pages. A 32-bit virtual address is split into a 12-bit page offset, which passes through translation unchanged, and a 20-bit virtual page number (VPN), which is split again into two 10-bit indices, VPN[1] and VPN[0]. The page table has two levels. Each page-table entry (PTE) is 4 bytes, so a 1024-entry table fills exactly one 4 KiB page. The satp CSR holds the mode, the physical page number of the root table, and an address-space identifier (ASID).

A page walk worked by hand

Translate virtual address 0x1234_5678. The values in the tables are made up for illustration.

  1. Split. VPN[1] = bits 31 to 22 = 0x048. VPN[0] = bits 21 to 12 = 0x345. Offset = bits 11 to 0 = 0x678.
  2. Level 1. Suppose satp holds root PPN 0x80000, so the root table is at physical 0x8000_0000. The PTE address is root + VPN[1] × 4 = 0x8000_0120. Read it. Say it is valid with R, W and X all zero: that means "pointer to the next level", with PPN 0x80001.
  3. Level 0. The next table is at 0x8000_1000. The PTE address is 0x8000_1000 + 0x345 × 4 = 0x8000_1D14. Read it. Say it is valid, with R and W set, and PPN 0x8ABCD. It is a leaf.
  4. Check permissions against the access type and privilege (the U bit, and the SUM and MXR controls in sstatus), and check the accessed (A) and dirty (D) bits. If anything fails, raise a precise page fault.
  5. Form the address. PPN joined with the offset: 0x8ABC_D678.

If the level-1 entry had been a leaf, with R or X set, it would map a 4 MiB megapage directly, and the walk would stop after one read. A leaf at level 1 must have its low PPN bits zero; otherwise the entry is misaligned and the access faults.

Two dependent memory reads, each of which may itself miss in the data cache, sit in front of every access. That is far too slow to do every time.

The TLB and what limits it

A TLB is a small cache of recent translations: VPN in, PPN and permission bits out. On a hit, translation costs nothing extra; on a miss, the walker runs and refills an entry. Because it must answer quickly, a level-1 TLB is small and often fully associative.

The figure that matters is reach: entries × page size. Sixty-four entries of 4 KiB pages cover 256 KiB. A program whose working set is spread over a few megabytes misses in the TLB constantly, even if its data fit in the cache. The same 64 entries holding 4 MiB megapages would reach 256 MiB. Superpages are therefore the main tool for large, contiguous mappings such as the kernel's own memory or big buffers, at the cost of coarser protection and more fragmentation.

The effective translation cost is easy to estimate. With a 99% hit rate and a miss that takes two memory reads of 30 cycles each (illustrative numbers), the average is 0.01 × 60 = 0.6 cycles per access. A 1% miss rate looks small until you multiply it by every load and fetch.

Design choices that keep the TLB correct and fast

  • ASIDs. Without them, every context switch must flush the TLB, because process A's VPN 0x10 is not process B's. Tagging entries with the ASID from satp lets translations from several processes coexist. Entries for global mappings (the G bit) match any ASID.
  • sfence.vma. The TLB is not kept coherent with page-table memory by hardware. After the operating system changes a PTE, it must execute sfence.vma, optionally limited to one address or one ASID, before relying on the change. Forgetting it gives a stale mapping that works until it suddenly does not.
  • A and D bits. The privileged specification allows the hardware either to set them during a walk or to raise a page fault so software sets them. Either is legal; software must handle both.
  • Hardware or software walk. RISC-V application cores normally walk the table in hardware. The walker is a small state machine, but it needs a path into the memory system and careful interaction with the caches.
  • VIPT level-1 caches. To overlap the TLB lookup with the cache lookup, many designs index the cache with untranslated offset bits and compare physical tags. That works without aliasing only if the bits used for index and line offset fit inside the 12-bit page offset: cache size divided by ways must be at most 4 KiB. A 32 KiB cache must then be at least 8-way. This is a real constraint that links the page size to the L1 cache shape.

Common mistakes

  • Treating the TLB as transparent. It is a cache that software must manage with sfence.vma.
  • Ignoring TLB reach when profiling. A slowdown that scales with working-set size, not data size, is often TLB misses.
  • Mixing up a pointer PTE and a leaf. R = W = X = 0 means "next level"; anything else is a leaf.
  • Growing a VIPT cache by adding sets. It breaks the no-alias condition; add ways instead or handle aliases.

Try it yourself

  1. Write a Python Sv32 walker that takes a dictionary of physical memory words, a satp value and a virtual address, and returns the physical address or the fault type. Check it against the worked example.
  2. Boot a small RISC-V Linux image in QEMU (qemu-system-riscv32 -machine virt) and use the QEMU monitor command info mem to list the current virtual-to-physical mappings.
  3. Model a 16-entry fully associative TLB in your Python walker, replay an address trace and measure the hit rate with and without megapages.
