Your first circuit in Xschem and ngspice: an inverter from schematic to transient plot

Analog & mixed-signal Beginner 27 Nov 2026 5 min read By Ketuna

Draw a CMOS inverter in Xschem with sky130 transistors, generate a SPICE netlist, simulate it in ngspice and measure its delay. Each step explains what the tool is doing so you can debug it yourself.

Every analog designer's first real simulation is an inverter, and it is worth doing carefully. It exercises the whole open-source flow: a schematic editor (Xschem), an open process design kit (sky130), a netlister and a circuit simulator (ngspice). When something breaks later in a bigger design, it is nearly always one of the links you set up here. This walk-through keeps each step small and says what is happening underneath, so that when a step fails you know where to look.

What you need and how the pieces fit

Install three things: Xschem, ngspice and the sky130 PDK with its Xschem symbol library. Package managers and the PDK's own installers handle this; the details change with versions, so follow the current instructions of each project.

The flow is a chain:

  1. Xschem holds a schematic: symbols and wires.
  2. Each symbol carries a template that tells Xschem what SPICE line to write for it. Generating the netlist turns the drawing into a text file.
  3. ngspice reads that text file, plus the PDK's model library, which describes how sky130 transistors behave, and runs the analyses you ask for.

The model library is the link people forget. Transistor symbols only name a device such as sky130_fd_pr__nfet_01v8; the equations live in the PDK's ngspice files, pulled in with a .lib line that also selects a process corner such as tt.

Step 1: draw the inverter

Start Xschem from a directory where the PDK's xschemrc is visible, so that the sky130 libraries load. Open a new schematic.

  • Insert a PMOS (pfet_01v8) and an NMOS (nfet_01v8) from the sky130 symbol library. Xschem's insert-symbol command is on the Insert key and in the menus.
  • Set their sizes by editing properties (select the symbol and press q): for a first try, NMOS W = 1, L = 0.15 and PMOS W = 2, L = 0.15, in micrometres. The PMOS is wider because holes are slower than electrons.
  • Wire them (the w key starts a wire): PMOS source and body to a node vdd, NMOS source and body to ground, both drains to a node out, both gates to in. Name nodes with label pins rather than relying on wire names.
  • Add a load capacitor of 10 fF from out to ground, so the delay you measure reflects some fan-out instead of a bare drain.

Two voltage sources complete the circuit: a DC supply of 1.8 V on vdd, and a pulse source on in.

Step 2: tell ngspice what to do

The analysis commands go into a code block on the schematic. Xschem provides a code symbol (code_shown.sym in the standard device library) whose text is copied into the netlist. The PDK's Xschem library also provides a corner symbol that writes the .lib line; if you prefer, put the .lib line in the code block yourself.

The netlist Xschem generates will look much like this (the exact model path depends on your install):

* inverter test bench
.lib "sky130A/libs.tech/ngspice/sky130.lib.spice" tt
XMP out in vdd vdd sky130_fd_pr__pfet_01v8 W=2 L=0.15
XMN out in 0 0 sky130_fd_pr__nfet_01v8 W=1 L=0.15
CL out 0 10f
VDD vdd 0 1.8
VIN in 0 PULSE(0 1.8 1n 50p 50p 2n 4n)
.control
tran 1p 10n
plot v(in) v(out)
meas tran tphl trig v(in) val=0.9 rise=1 targ v(out) val=0.9 fall=1
meas tran tplh trig v(in) val=0.9 fall=1 targ v(out) val=0.9 rise=1
.endc
.end

Read it once line by line; you will debug at this level for the rest of your career.

  • XMP and XMN start with X because sky130 transistors are wrapped in subcircuits. The four nodes are drain, gate, source and body.
  • PULSE(0 1.8 1n 50p 50p 2n 4n) means: low level 0 V, high level 1.8 V, delay 1 ns, rise and fall 50 ps, high for 2 ns, period 4 ns.
  • tran 1p 10n runs a transient analysis for 10 ns with a 1 ps suggested step.
  • The two meas lines measure propagation delay from the input crossing half the supply to the output crossing half the supply, once for a falling output (tpHL) and once for a rising one (tpLH).

Step 3: netlist, simulate, read

Use Xschem's Netlist button, then Simulate, which launches ngspice with the generated file. You should see the input pulse and an inverted, slightly delayed output, and the two delays printed in the ngspice console.

Before trusting the numbers, sanity-check them against a hand estimate. Delay is roughly 0.69 × Ron × CL. If the transistor's effective on-resistance is a few kilohms and the load is 10 fF plus the drain capacitances, you expect tens of picoseconds. A result in nanoseconds or femtoseconds means something is wrong, usually a unit error such as W=1e-6 written where the PDK expects micrometres, or a missing load.

Then compare the two delays. If tpLH is much longer than tpHL, the PMOS is too weak; widen it and run again. Looking at both edges and adjusting one width is your first real piece of transistor sizing.

When it does not work

Most first-run failures fall into a few groups:

  • "Unknown model" or "unknown subcircuit". ngspice cannot find the transistor definitions. The .lib line is missing, the path is wrong, or the corner name is misspelt.
  • Symbols not found when opening Xschem. It was started without the PDK's xschemrc, so the sky130 library paths are not set.
  • Floating node errors. A body terminal or a gate is unconnected. Every node needs a DC path to ground.
  • Flat output. The supply source is not connected to the same net name as the PMOS source; a label spelt vdd in one place and vcc in another creates two separate nets. (SPICE ignores letter case, so VDD and vdd are the same node.)
  • Simulation is very slow. The time step is far smaller than needed, or the stop time is far longer; start with a few periods.

Try it yourself

  1. Draw the inverter in Xschem, generate the netlist and compare it line by line with the one above.
  2. Simulate it in ngspice, record tpHL and tpLH, then double the load capacitor and check that both delays roughly double.
  3. Add a .dc VIN 0 1.8 0.005 analysis in a second code block, plot the transfer curve, and use meas dc vm when v(out)=v(in) to find the switching point. Change the corner from tt to ss and ff and note how the delay and switching point move.
