How a SAR ADC converts: binary search with a capacitor DAC

Analog & mixed-signal Intermediate 27 Nov 2026 5 min read By Ketuna

A successive-approximation ADC finds a digital code by binary search, one comparator decision per bit. Follow the sample, compare and bit-trial sequence, and see why the capacitor array sets the accuracy.

In this article

The successive-approximation register (SAR) ADC is the converter inside most microcontrollers and a large share of sensor interfaces. It hits a useful middle ground: moderate speed, resolutions from 8 to 16 bits, low power and small area, all from one comparator, an array of capacitors and a small block of logic. The way it converts is a binary search, the same algorithm you use to guess a number between 1 and 100 in seven questions. The interesting engineering is in how the capacitors make the "guess" voltages and why their matching decides accuracy.

The algorithm: guess, compare, keep or clear

An N-bit SAR conversion has three phases.

  1. Sample. The input voltage is captured onto a capacitor and held. From now on the input may change; the converter works on the held copy.
  2. Bit trials. Starting with the most significant bit (MSB), the logic tentatively sets the bit to 1 and asks a digital-to-analog converter (DAC) for the corresponding voltage. A comparator checks whether the held input is above or below it. If above, the bit stays 1; if below, it is cleared to 0. Then the next bit is tried, with all previous decisions kept.
  3. Done. After N trials, the register holds the code.

Each trial halves the uncertainty, so N bits take N comparator decisions. That is why a SAR converter's conversion time grows linearly with resolution and why it needs an internal clock running several times faster than the sample rate.

A worked example

A 6-bit SAR with a 3.2 V reference has an LSB of 3.2 / 64 = 50 mV. Convert a held input of 2.13 V:

Trial Code tried DAC voltage Decision
Bit 5 (MSB) 100000 1.600 V 2.13 ≥ 1.60, keep
Bit 4 110000 2.400 V 2.13 < 2.40, clear
Bit 3 101000 2.000 V keep
Bit 2 101100 2.200 V clear
Bit 1 101010 2.100 V keep
Bit 0 101011 2.150 V clear

The result is 101010, decimal 42, which represents 42 × 50 mV = 2.10 V, the largest code step at or below the input.

The capacitor DAC does two jobs

In a CMOS SAR the DAC is usually an array of binary-weighted capacitors: C, 2C, 4C and so on up to 2N−1C, plus one extra unit capacitor so the total is exactly 2NC. All the top plates connect to the comparator input.

During sampling, the bottom plates connect to the input voltage, so the array stores a charge proportional to Vin; the array is the sample-and-hold. During the bit trials, the top plates are left floating, so the stored charge cannot escape, and the bottom plates switch to either the reference or ground according to the trial code. Because charge is conserved, the top-plate voltage becomes:

Vtop = −Vin + Vref × (capacitance switched to Vref) / Ctotal

The comparator only needs to check the sign of Vtop. Switching the 32C capacitor alone gives Vref × 32/64, half of full scale: exactly the MSB trial. This is called charge redistribution, and it is attractive because capacitors draw no static current and are among the best-matched components on a chip.

Why the capacitor array sets the accuracy

The DAC's voltages are ratios of capacitances, so the converter is only as linear as those ratios are accurate. The worst place is the middle of the range. Going from code 011111 to 100000 switches off every capacitor except the MSB and switches the MSB on. Ideally the MSB equals the sum of all the smaller ones plus one unit. If the MSB is 1 % too large, it carries 0.32 units of extra capacitance, and the step from code 31 to code 32 is 1.32 LSB instead of 1: a DNL error of about +0.32 LSB right at mid-scale. If it is too small by enough, the step shrinks towards zero and a code goes missing.

The model below makes this concrete; set msb_error=0.01 and sweep the input to see the wide mid-scale code.

def sar_convert(vin, vref=3.2, nbits=6, msb_error=0.0, trace=False):
    """Model a SAR ADC with a binary-weighted capacitor DAC."""
    caps = [2 ** i for i in range(nbits)]   # C, 2C, ..., 32C (LSB first)
    caps[-1] *= 1 + msb_error               # mismatch on the MSB cap
    c_total = sum(caps) + 1                 # plus the unit dummy cap
    code = 0
    for bit in reversed(range(nbits)):      # MSB first
        trial = code | (1 << bit)
        on = sum(c for i, c in enumerate(caps) if trial >> i & 1)
        v_dac = vref * on / c_total
        keep = vin >= v_dac                 # the comparator decision
        if keep:
            code = trial
        if trace:
            print(f"bit {bit}: try {trial:06b}  DAC {v_dac:.3f} V  "
                  f"{'keep' if keep else 'clear'}")
    return code

print("result:", sar_convert(2.13, trace=True))

Designers fight mismatch by building every capacitor from identical unit cells placed in a common-centroid pattern, and at high resolution by calibrating the capacitor weights digitally. The array cannot be made arbitrarily small either. Sampling onto a capacitor freezes thermal noise with an rms value of √(kT/C): about 64 µV for 1 pF at room temperature. That is harmless for 12 bits on 3.3 V (LSB about 0.8 mV) but comparable to an LSB at 16 bits, so higher resolution forces a larger array, more area and more power in the drivers.

Other practical limits:

  • Comparator offset and noise add directly to the decision threshold; offset only shifts the transfer curve, but noise causes wrong decisions on nearby codes.
  • Reference settling: each trial switches capacitors on the reference, drawing charge. If the reference has not settled before the comparator fires, the decision is wrong. Reference buffering is often harder than the comparator.
  • Input drive: the source must charge the whole array within the sampling time, which is why datasheets limit source impedance or recommend a buffer.

Try it yourself

  1. Run the Python model, then sweep vin from 0 to 3.2 V in fine steps with msb_error=0.01 and -0.04. Compute the width of each code and find the mid-scale DNL.
  2. Write the SAR control logic in Verilog (a shift register plus a code register driven by a comparator input), simulate it with Icarus Verilog against a behavioural comparator, and check that six clocks give the codes in the table.
  3. In ngspice, build a 4-bit charge-redistribution array with ideal switches and capacitors, and watch the top-plate voltage step through the trials.
