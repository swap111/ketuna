The MOSFET in three regions: an intuition-first guide

Analog & mixed-signal Beginner 27 Nov 2026 6 min read By Ketuna

A MOSFET is off, behaves like a resistor, or behaves like a current source, depending on two voltages. Build the picture with water flow first, then the square-law equations and a worked example.

Every chip you will ever design is made of MOSFETs, and almost every confusing simulation result in a first analog circuit comes down to one question: which region is this transistor in? A MOSFET can be off, it can act like a voltage-controlled resistor, or it can act like a current source. Learn to tell these three apart at a glance and the equations stop feeling arbitrary.

The device in one paragraph

An NMOS transistor has four terminals. The source and drain are two n-type regions in a p-type body. Between them, over a thin insulating oxide, sits the gate. With no gate voltage, source and drain are separated by p-type silicon and no current flows. Raise the gate voltage relative to the source (VGS) and the gate's electric field pulls electrons to the surface under the oxide. Above a certain threshold voltage VTH, those electrons form a thin conducting channel that joins source to drain. A PMOS device is the mirror image, with holes instead of electrons and all the voltage signs reversed.

The amount by which VGS exceeds the threshold is called the overdrive voltage:

VOV = VGS − VTH

Overdrive is the single most useful number in hand analysis. It says how strongly the channel is formed.

A water-flow picture

Picture the source as a water tank and the drain as a lower tank, joined by a channel with a sluice gate. The gate voltage sets how high the sluice gate is lifted, which sets how deep the water in the channel can be. The drain voltage sets how far the downstream tank sits below the source tank.

  • Cut-off: the sluice gate is shut (VGS below VTH). No channel, almost no flow, whatever the tank heights. A tiny seepage remains; in a real transistor this is subthreshold leakage, which grows exponentially as VGS approaches VTH.
  • Triode: the gate is open and the downstream tank is only a little lower (small VDS). Water depth is nearly even along the channel, and flow is roughly proportional to the height difference. The channel behaves like a resistor whose value the gate controls.
  • Saturation: lower the downstream tank further and the water at the drain end of the channel gets shallower until it "pinches off". Beyond that point, dropping the downstream tank more does not increase the flow much, because the flow is now limited by how much water the gate lets into the channel. The transistor acts like a current source set by VGS.

The boundary between triode and saturation is where the drain end pinches off: VDS = VOV.

The square-law equations

For a long-channel NMOS, three regions give three expressions. Here μnCox is a process constant (electron mobility times oxide capacitance per area), W/L is the width-to-length ratio you choose, and λ is a small factor for channel-length modulation.

Region Condition Drain current ID
Cut-off VGS < VTH ≈ 0
Triode VDS < VOV μnCox(W/L)[VOVVDS − VDS2/2]
Saturation VDS ≥ VOV ½μnCox(W/L)VOV2(1 + λVDS)

Two things to notice. First, at VDS = VOV the triode expression equals the saturation one (with λ = 0), so the curves join smoothly. Second, in saturation VDS appears only in the small (1 + λVDS) term. That is the mathematical form of "the flow no longer depends much on the downstream tank". The λ term exists because a higher drain voltage shortens the effective channel a little, so current creeps up slowly.

A worked example

Take an NMOS with μnCox = 200 µA/V2, W/L = 5 and VTH = 0.5 V. These numbers are made up for illustration and ignore λ. Set VGS = 0.8 V, so VOV = 0.3 V.

  • VDS = 1.0 V: 1.0 ≥ 0.3, so saturation. ID = ½ × 200 µA/V2 × 5 × 0.32 = 45 µA.
  • VDS = 0.1 V: 0.1 < 0.3, so triode. ID = 200 µA/V2 × 5 × (0.3 × 0.1 − 0.12/2) = 25 µA.
  • VDS = 0.3 V: right on the boundary. Both formulas give 45 µA.

Now repeat the first case with the saturation formula applied blindly at VDS = 0.1 V: you would predict 45 µA instead of 25 µA, an error of 80 %. Checking the region first is not pedantry.

A short function makes the decision explicit, and is a good habit to keep beside your simulator:

def nmos_id(vgs, vds, k=200e-6, wl=5, vth=0.5, lam=0.0):
    """Long-channel square-law drain current, in amperes."""
    vov = vgs - vth
    if vov <= 0:
        return 0.0, "cut-off"
    if vds < vov:
        return k * wl * (vov * vds - vds**2 / 2), "triode"
    return 0.5 * k * wl * vov**2 * (1 + lam * vds), "saturation"

for vds in (0.1, 1.0):
    i, region = nmos_id(0.8, vds)
    print(f"VDS={vds:.1f} V  ID={i*1e6:5.1f} uA  {region}")

Where the square law stops being true

The square law describes long-channel devices. In modern short-channel transistors, carriers hit a speed limit in strong electric fields (velocity saturation), so current grows more slowly than VOV2. The threshold also drops as VDS rises, an effect called drain-induced barrier lowering. Real design uses detailed compact models such as BSIM inside SPICE.

So why learn the square law at all? Because it gives you the right shape and roughly the right size, which is what you need to choose a starting bias and to spot a simulation that has gone wrong.

Common mistakes beginners make:

  • Using the saturation formula without checking VDS ≥ VOV
  • Forgetting that PMOS equations use VSG, VSD and |VTH|, so every sign flips
  • Calling the triode region "linear" and then expecting it to be linear at large VDS; the VDS2 term bends it
  • Confusing MOSFET "saturation" (current is flat) with bipolar "saturation" (the transistor is fully on), which mean nearly opposite things

Try it yourself

  1. Install ngspice and an open PDK such as sky130. Write a netlist with one sky130_fd_pr__nfet_01v8 device and run .dc VDS 0 1.8 0.01 VGS 0.4 1.0 0.2 to plot the output curves.
  2. On each curve, mark the point where VDS = VGS − VTH, using the threshold reported by an op run, and check that the curve flattens there.
  3. Run the Python function above with your own numbers, then compare its current with the simulator at one bias point. Expect a difference, and write down why.
