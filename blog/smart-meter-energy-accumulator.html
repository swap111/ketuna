Building the energy accumulator of a smart meter in fixed-point RTL

Digital & VLSI design Advanced 27 Nov 2026 5 min read By Ketuna

Multiply voltage and current samples, accumulate the products without overflow, and emit one calibrated pulse per fixed quantum of energy. A worked sizing of every register, checked with a Python model.

An electricity meter's core job is simple to state: integrate power over time. Digitally, that means multiplying each voltage sample by the matching current sample, adding the products up forever, and producing an output, often a pulse on an LED and a register value, every time a fixed amount of energy has passed. The arithmetic is a few lines of RTL. The engineering is in the widths: every register must be sized so that it never overflows, never loses resolution that matters, and maps cleanly onto a calibrated physical unit.

From samples to energy

Assume the analog front end delivers signed 16-bit voltage and current codes at a fixed sample rate. Instantaneous power is p = v × i. Energy is the sum of power times the sample interval:

E = Σ vn × in × Ts

Active (real) power is the average of v × i, so summing the raw products automatically accounts for the phase difference between voltage and current: a load that draws current out of phase contributes partly negative products, and the sum reflects only the real energy delivered. No explicit power-factor calculation is needed.

Choosing the scale factors

Use these values, made up for illustration:

Quantity Value
Voltage LSB 10 mV per code
Current LSB 2 mA per code
Sample rate fs 4000 samples per second
Meter constant 3200 pulses per kWh

One unit of the product v × i is 10 mV × 2 mA = 20 µW. Each sample covers 1/4000 s, so one product unit accumulated for one sample is 20 µW / 4000 = 5 × 10−9 J.

One kilowatt-hour is 3.6 × 106 J, so one pulse at 3200 pulses per kWh is 3.6 × 106 / 3200 = 1125 J. The accumulator threshold for one pulse is therefore:

TH = 1125 J / 5 × 10−9 J = 2.25 × 1011 product-units

Sizing every register

The product. Two signed 16-bit numbers give a signed 32-bit product. With the scale chosen above, the full-scale codes are ±327.67 V and ±65.5 A, far beyond what a household line delivers, so the real products are much smaller, but the register must hold the worst case: 32 bits.

The accumulator. It holds the running sum until it crosses TH, then TH is subtracted. Its value never exceeds TH plus one maximum product. TH needs log2(2.25 × 1011) ≈ 37.7, so 38 bits; one product is at most about 230. Their sum stays below 238 ≈ 2.75 × 1011, so 38 magnitude bits plus a sign bit suffice. Use a 48-bit accumulator: the extra bits cost little and leave room for calibration to raise the threshold, or for a different meter constant.

The pulse rate. At the theoretical maximum power, 327.67 V × 65.5 A ≈ 21.5 kW, a pulse comes every 1125 / 21,474 ≈ 52 ms, about 210 samples apart. So at most one pulse can be due per sample, and a single compare-and-subtract per sample is enough. If your scaling made pulses possible more often than once per sample, you would need a loop or a divider instead.

The RTL

module energy_acc (
  input  logic               clk, rst_n,
  input  logic               smp_valid,      // one per sample period
  input  logic signed [15:0] v, i,           // matched samples
  input  logic        [47:0] th,             // calibrated threshold
  output logic               pulse           // one cycle per quantum
);
  logic signed [31:0] p_q;
  logic               p_valid;
  logic signed [47:0] acc;

  always_ff @(posedge clk or negedge rst_n)
    if (!rst_n) begin
      p_valid <= 1'b0; acc <= '0; pulse <= 1'b0;
    end else begin
      p_valid <= smp_valid;
      pulse   <= 1'b0;
      if (smp_valid) p_q <= v * i;           // stage 1: multiply
      if (p_valid) begin                     // stage 2: accumulate
        if (acc + p_q >= $signed({1'b0, th[46:0]})) begin
          acc   <= acc + p_q - $signed({1'b0, th[46:0]});
          pulse <= 1'b1;
        end else
          acc   <= acc + p_q;
      end
    end
endmodule

The multiply and accumulate are in separate stages, so the critical path is one 16 × 16 multiplier or one 48-bit add and compare, never both. At a few thousand samples per second this is nowhere near a timing problem, so the same datapath can easily be shared across phases or channels by time multiplexing. The pulse is a single clock wide; a small timer stretches it to whatever width the LED or opto-isolator needs.

Because the subtraction keeps the remainder, no energy is lost at each pulse: the residue carries over into the next quantum. That is what makes the long-term pulse count exact, apart from the measurement errors in the front end.

Calibration

Real sensors have gain errors. Rather than multiplying every sample by a correction factor, put the correction in the threshold: if the current channel reads 2 % high, raise th by 2 %. One register, written during factory calibration, corrects the gain of the whole chain at no per-sample cost. Offset errors are handled before the multiplier, usually with a high-pass filter or offset subtraction on each channel, and phase errors between the voltage and current paths with a small delay or phase correction, because both directly bias the product.

Checking it against a model

Write a Python model that feeds a known load and counts pulses. With 230 V rms, 5 A rms and a power factor of 0.8, the load is 920 W, so the expected pulse period is 3600 / (0.92 × 3200) ≈ 1.2228 s.

import numpy as np

FS = 4000                      # samples per second
V_LSB, I_LSB = 0.010, 0.002    # volts and amps per code
TH = 225_000_000_000           # product-units per pulse

t = np.arange(10 * FS) / FS                         # 10 seconds
v = np.round(230 * np.sqrt(2) * np.sin(2*np.pi*50*t) / V_LSB)
i = np.round(5 * np.sqrt(2) * np.sin(2*np.pi*50*t - np.arccos(0.8)) / I_LSB)
v, i = v.astype(np.int64), i.astype(np.int64)

acc, pulses = 0, []
for n, p in enumerate(v * i):
    acc += int(p)
    if acc >= TH:
        acc -= TH
        pulses.append(n / FS)
print(len(pulses), np.diff(pulses).mean())   # 8 pulses, about 1.2229 s

The model gives a mean period of about 1.2229 s, matching the hand calculation. Use the same vectors to drive the RTL and compare pulse times sample for sample.

Pitfalls

  • Exported energy. If power can flow back to the grid, the sum goes negative. Decide whether to keep separate import and export accumulators, as many tariffs require, and add a negative threshold.
  • Standards. Metering accuracy classes, test conditions and pulse output requirements are defined in the relevant IEC standards and Indian Standards for electricity meters. Check the current editions; they drive the design, not the other way round.
  • Safety. Meters connect to mains. Front-end and isolation design and any testing on live mains need qualified supervision.

Try it yourself

  1. Redo the sizing for your own scale factors on paper, then check every width with a few lines of Python.
  2. Run the model above, then simulate energy_acc in Verilator with the same integer samples written to a file, and compare pulse indices exactly.
  3. Change the power factor to 0.5 and to −0.8 (export) and confirm the pulse rate changes as expected, then add the export accumulator.
