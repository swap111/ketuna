The first day with your chip back from the fab: a bring-up plan

Physical design & tape-out Intermediate 27 Nov 2026 5 min read By Ketuna

Bring-up goes in a fixed order so that one fault cannot hide another or destroy the part. Learn a staged plan: current-limited power-up, clocks and reset, JTAG and scan, then functions, with everything recorded.

In this article
  1. Prepare before the chips arrive
  2. The staged sequence
  3. Record everything
  4. Common first-day mistakes
  5. Try it yourself

The packaged chips arrive after months of waiting, and the temptation is to plug one in, load the demo and see if it works. If it does not, you have learned almost nothing: the fault could be the board, the supply, the clock, the reset, the interface or the design itself, and an unlimited power supply may already have damaged the only die you had. A bring-up plan exists to answer one question at a time, in an order where each step can only pass if everything before it is right.

Prepare before the chips arrive

Most of a good first day is decided earlier.

  • Board checked without the chip. Bring up the board with the socket empty: correct rail voltages, no shorts between supplies and ground, clock source running, level shifters and connectors working.
  • Expected numbers written down. Idle current estimate for each supply, the clock frequency you will start at, the value of any ID register, and the response to the first test pattern. Without expected values, you cannot tell success from coincidence.
  • Simulation vectors ready to replay. The same stimulus your testbench used, converted into something the bench equipment or a microcontroller can drive.
  • A log file opened. Date, chip number, board number, supply settings, temperature if known, every measurement.

The staged sequence

1. Power with a current limit

Use a bench supply with an adjustable current limit. Set the voltage to nominal and the limit a modest amount above the expected idle current, for example a few times the estimate; the exact margin is a judgement call based on how confident your estimate is. Turn the supply on with the chip in its socket, reset held asserted if possible.

Read the current immediately. If the supply hits its limit, turn it off: there is a short, a package orientation error, or a latch-up condition. If the current is far below expectation, check that the chip is actually powered (continuity, socket contact). Only when each rail draws a sensible current do you continue. With multiple supplies, follow the power-up order your design requires.

Touch the package after a minute. A chip that is warm at idle when it should not be is telling you something.

2. Clock and reset

Apply the clock at a low frequency first, well below the design target, so that timing margins are generous and probing is easy. Release reset. Look for a sign of life designed in for this purpose: a clock-divided output pin, a heartbeat counter bit, a status pin that changes after reset. If you have nothing like this, the next stage is your first visible output.

Check that the current changes when the clock starts. A design that draws exactly the same current with and without a clock may not be receiving it.

3. JTAG and scan

These are the most structural tests you have, because they exercise a small, well-known part of the chip.

  • Read the JTAG ID code. If it returns the value you designed in, the TAP controller, its pins and its clock are working. Read it several times; it must be stable.
  • Shift a pattern through the scan chain in shift mode and compare what comes out with what went in, delayed by the chain length. This proves the chain is continuous and every scan flop can shift.
  • Run a few ATPG patterns if you have the equipment, at low speed.

A broken scan chain locates a manufacturing or design fault far more precisely than a failed functional test.

4. Basic functions

Now replay the simplest functional test from simulation: write a register and read it back, run a short computation, send a byte through the UART. Compare against expected output exactly. Then extend to more tests. When something fails, reduce the test until the smallest failing case is found, and compare with simulation at that point.

5. Sweeps and characterisation

Once the chip works at nominal conditions and low speed, sweep supply voltage and clock frequency, recording pass or fail at each point. Plotted as a grid, this is a shmoo plot. If failures move to higher frequencies as voltage rises, the limit is timing. If they do not depend on voltage, look for a functional, interface or test-setup cause.

Record everything

Log every measurement, including the boring ones. Log failures with the exact conditions. Number each chip and board and keep results per chip, because chips vary, and the second chip you test may behave differently from the first. A result you cannot reproduce later is not a result.

Common first-day mistakes

  • No current limit. One short with an unlimited supply can destroy the part.
  • Starting at full speed. A timing-limited failure then looks like a functional bug.
  • Changing two things at once. You lose the ability to say which change fixed or broke the behaviour.
  • Testing only one chip. One die can be defective while the design is fine, or the reverse.

Try it yourself

  1. Before any real silicon, rehearse with an FPGA or a simulated chip: write the bring-up plan for a design you have, with expected values at each stage.
  2. Simulate the JTAG ID read and a scan shift test in Icarus Verilog and save the vectors as files a bench script could replay.
  3. Write a small Python script that sweeps two variables (voltage and frequency) against a stub pass/fail function and prints a shmoo grid, ready to connect to real instruments later.
