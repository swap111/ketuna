Convolution layer arithmetic: output size, MACs and memory by hand

Edge AI Beginner 27 Nov 2026 5 min read By Ketuna

From kernel size, stride and padding to the output shape, then to multiply-accumulates, weights and activation bytes for one convolution layer, worked by hand and checked with a few lines of Python.

Convolutional layers are the workhorse of small vision and audio models, and they are where most of a network's arithmetic usually happens. Before you can say whether a model will fit a microcontroller or how long it will take, you need four numbers for each convolution: its output shape, its multiply-accumulate count, its weight count and its activation size. All four come from a handful of layer parameters and some multiplication. Working them out by hand once makes every later model summary readable.

What a convolution layer does

The input to a 2-D convolution is a feature map: a grid of height H and width W with Cin channels (for an RGB image, Cin = 3; for an audio spectrogram, often 1). A kernel (or filter) is a small block of weights of size K × K × Cin. The layer slides the kernel across the input; at each position it multiplies every kernel weight by the input value underneath and adds them up, giving one output number. A layer has Cout different kernels, so each position produces Cout outputs: the output feature map has Cout channels.

Two more parameters control the sliding:

  • Stride S: how many positions the kernel moves each step. Stride 2 skips every other position and roughly halves the output size.
  • Padding P: how many rows and columns of zeros are added around the input border. Padding of 1 with a 3 × 3 kernel keeps the output the same size as the input ("same" padding); no padding ("valid") shrinks it.

Output size

Along each spatial dimension:

Hout = ⌊(H + 2P − K) / S⌋ + 1

and the same for width. The floor means any leftover positions where the kernel would hang off the edge are dropped.

Check it on a few cases:

  • 5 × 5 input, K = 3, S = 1, P = 0: (5 − 3) / 1 + 1 = 3. That is the figure.
  • 32 × 32 input, K = 3, S = 1, P = 1: (32 + 2 − 3) / 1 + 1 = 32. Same padding keeps the size.
  • 32 × 32 input, K = 3, S = 2, P = 0: ⌊29 / 2⌋ + 1 = 14 + 1 = 15.
  • 32 × 32 input, K = 3, S = 2, P = 1: ⌊31 / 2⌋ + 1 = 16.

The last two show why padding matters with stride: the same layer gives 15 or 16 depending on one row of zeros, and a mismatch between your training framework and your hand calculation shows up here first.

Counting MACs, weights and activations

Take a worked example: a 32 × 32 RGB input (Cin = 3), a 3 × 3 kernel, 16 filters, stride 1, padding 1. The output is 32 × 32 × 16.

MACs. Every output value needs one full kernel's worth of multiply-accumulates, K × K × Cin = 3 × 3 × 3 = 27. There are 32 × 32 × 16 = 16,384 output values, so:

MACs = Hout × Wout × Cout × K × K × Cin = 32 × 32 × 16 × 27 = 442,368

Weights. Each of the 16 filters has 27 weights: 3 × 3 × 3 × 16 = 432 weights, plus 16 biases. In int8 with int32 biases, that is 432 + 64 = 496 bytes. Tiny.

Activations. The input is 32 × 32 × 3 = 3,072 values and the output 32 × 32 × 16 = 16,384 values. In int8, the layer needs 3,072 + 16,384 = 19,456 bytes of RAM while it runs, because the input and output both exist at that moment.

Notice the contrast. The weights fit in under 500 bytes, yet the layer performs nearly half a million MACs and needs about 19 kB of RAM. Each weight is reused at every one of the 1,024 output positions. That reuse is why convolutions suit parallel hardware, and why on microcontrollers it is usually activation RAM, not weight flash, that limits image models.

Changing the stride to 2 (with padding 1) makes the output 16 × 16 × 16: the MACs drop by four to 110,592, the output activations by four to 4,096 bytes, and the weights stay exactly the same.

A depthwise-separable comparison

Small models often replace a standard convolution with a depthwise-separable one: a 3 × 3 depthwise convolution that filters each input channel separately, followed by a 1 × 1 pointwise convolution that mixes channels. For a 32 × 32 map going from 16 to 32 channels:

  • standard: 32 × 32 × 32 × 3 × 3 × 16 = 4,718,592 MACs
  • depthwise: 32 × 32 × 16 × 3 × 3 = 147,456 MACs
  • pointwise: 32 × 32 × 32 × 16 = 524,288 MACs

The separable version needs 671,744 MACs, about 7 times fewer, for a similar job. It usually costs some accuracy and is harder to quantize, which is why the trade-off is measured rather than assumed.

A helper to check your arithmetic

def conv2d_cost(h, w, c_in, c_out, k, s=1, p=0, bytes_per_act=1):
    h_out = (h + 2 * p - k) // s + 1
    w_out = (w + 2 * p - k) // s + 1
    macs = h_out * w_out * c_out * k * k * c_in
    weights = k * k * c_in * c_out
    act_bytes = (h * w * c_in + h_out * w_out * c_out) * bytes_per_act
    return (h_out, w_out, c_out), macs, weights, act_bytes

print(conv2d_cost(32, 32, 3, 16, 3, s=1, p=1))
# ((32, 32, 16), 442368, 432, 19456)

Do the numbers on paper first, then run the helper, then compare with your framework's model summary. When all three agree, you understand the layer.

Common mistakes:

  • forgetting Cin in the MAC count, which underestimates by the number of input channels
  • treating parameter count as cost: this layer has 432 weights but 442,368 MACs
  • assuming "same" padding with stride 2 gives exactly half the size without checking odd input sizes
  • counting only output activations and forgetting that the input is still alive

Try it yourself

  1. Work out by hand the output shape, MACs, weights and activation bytes for a 49 × 10 × 1 spectrogram input, 3 × 3 kernel, 8 filters, stride 1, padding 1.
  2. Check your answer with conv2d_cost, then build the layer in PyTorch with nn.Conv2d(1, 8, 3, padding=1) and confirm the output shape with a random input tensor.
  3. Repeat with stride 2 on the 10-wide axis and see which dimension shrinks to 5.
  4. Count the total MACs of a small CNN from a tutorial layer by layer and find which layer dominates.
