Data hazards and forwarding paths, traced cycle by cycle

Computer architecture & RISC-V Intermediate 27 Nov 2026 5 min read By Ketuna

Trace read-after-write hazards on a five-stage pipeline diagram, see which bypass path covers each distance between producer and consumer, and write the forwarding unit with the right priority.

In this article

  2. Which path covers which distance

In a five-stage pipeline, an instruction reads its source registers in the decode stage but its producer may not write the result back for another two or three cycles. Without help, the consumer reads a stale value and the program computes the wrong answer. Forwarding, also called bypassing, is the set of wires and multiplexers that delivers a result to the instruction that needs it before the register file has it. The clearest way to understand it is to draw the pipeline cycle by cycle and look at where each value is at each moment.

The read-after-write hazard

The only data hazard in a simple in-order pipeline is read after write (RAW): a younger instruction reads a register that an older instruction writes. Consider:

add x1, x2, x3     # producer: writes x1
sub x4, x1, x5     # needs x1 one instruction later
and x6, x1, x7     # needs x1 two instructions later
or  x8, x1, x9     # needs x1 three instructions later

The classic stages are IF, ID (register read), EX (ALU), MEM and WB (register write). Lay the four instructions out on a timing table:

Instruction C1 C2 C3 C4 C5 C6 C7
add x1, x2, x3 IF ID EX MEM WB
sub x4, x1, x5 IF ID EX MEM WB
and x6, x1, x7 IF ID EX MEM WB
or x8, x1, x9 IF ID EX MEM

The add computes x1 at the end of C3, but writes it into the register file only in C5. Now look at the bold cells, the moments when each consumer actually needs x1.

Which path covers which distance

  • Distance 1 (sub). In C4 the subtract is in EX and needs x1 at its ALU input. The add has just moved into MEM, so its result sits in the EX/MEM pipeline register. A wire from EX/MEM back to the ALU input multiplexer delivers it.
  • Distance 2 (and). In C5 the AND is in EX. The add is now in WB, and its result sits in the MEM/WB register. A second wire from MEM/WB to the ALU multiplexer covers this case.
  • Distance 3 (or). In C5 the OR is in ID, reading the register file in the same cycle that the add writes it. If the register file writes in the first half of the cycle and reads in the second, or bypasses internally when the read and write addresses match, the OR sees the new value. No pipeline forwarding is needed, but the register file must be built this way.
  • Distance 4 and more. The value is already in the register file. Nothing to do.

The forwarding unit, with the right priority

The forwarding unit compares the source register numbers of the instruction in EX with the destination numbers of the two older instructions ahead of it. Three conditions must hold for a forward: the older instruction writes a register, its rd is not x0, and its rd equals the source.

// Operand A; operand B is identical with idex_rs2.
// 2'b00 = ID/EX value, 2'b10 = EX/MEM, 2'b01 = MEM/WB
always @(*) begin
  fwd_a = 2'b00;
  if (exmem_regwrite && exmem_rd != 5'd0 &&
      exmem_rd == idex_rs1)
    fwd_a = 2'b10;            // youngest producer wins
  else if (memwb_regwrite && memwb_rd != 5'd0 &&
           memwb_rd == idex_rs1)
    fwd_a = 2'b01;
end

The order of the if and else if matters. Consider this sequence:

add  x1, x2, x3
addi x1, x1, 1
sub  x4, x1, x5

When sub reaches EX, addi is in MEM and add is in WB. Both have rd = x1, so both comparisons match. The correct value is the one from addi, the more recent write, which is in EX/MEM. Checking MEM/WB first would forward the add's older value and silently produce a result off by one. This is a classic bug, and it passes any test that never writes the same register twice in a row.

The x0 check matters too. An instruction such as addi x0, x5, 7 is a legal way to discard a result, but its ALU output is 7, not zero. Without the check, the next instruction that reads x0 would receive 7.

What forwarding saves

Without forwarding, the only safe option is to stall the consumer in ID until the producer has written back. With a write-then-read register file, a distance-1 dependency costs two bubble cycles and a distance-2 dependency costs one. Back-to-back dependent arithmetic is very common in real code (think of address calculations and loop counters), so these stalls would add up quickly. With the two bypass paths, every ALU-to-ALU dependency runs at full speed. The one case forwarding cannot fully cover is a load followed immediately by a use of its result, because the loaded data appears only at the end of MEM. That case keeps one stall and is explained in the load-use hazard.

Common mistakes

  • Wrong priority. MEM/WB checked before EX/MEM forwards stale data when both match.
  • No x0 check. A discarded result leaks into later reads of x0.
  • Forgetting the store data path. A store's rs2 value also needs forwarding, not only the ALU operands.
  • A register file without write-through. Distance-3 dependencies read the old value in ID.
  • Testing only independent instructions. Directed tests must cover distances 1, 2 and 3, and the double-write case.

Try it yourself

  1. Write the three-instruction double-write sequence above into a test program and predict every register value by hand.
  2. Run it on a pipelined RV32I core in Icarus Verilog or Verilator, swap the priority of the two comparisons on purpose, and watch the result go wrong in GTKWave.
  3. Compare the core with an instruction set simulator such as Spike, retiring instruction by instruction, so that any wrong forward is caught at the exact instruction where it happens.
